### Key per-repo findings

**NYUMedML** — split confirmed empirically (train 463 / val 99 / test 96
subjects, ~4 sessions each, zero pairwise overlap), but there is *no split
code in the repo*; it lives in shipped TSVs. Real bug in `datasets/adni_3d.py`:
the label filter is discarded in Train mode (second assignment re-indexes the
original frame), so EMCI/LMCI would be dropped in val/test but become
`label = -100` in train. Backbone is a plain 4-block dilated conv stack, NOT a
ResNet; input 96³. **Landmine:** blocks 3 and 4 both `add_module('pool2_s1',…)`,
so the net effectively has 3 pools, not 4 — the arithmetic only lands on the
hardcoded `5*5*5` because of this. It already ships `LinearRegressor_mmse`
alongside the classifier — the closest thing to our DEMO+ALZ dual head.
Preprocessing needs Clinica + SPM12 + MATLAB + FreeSurfer 6.0 (not Colab-able).

**brain2020** — `utils.read_csv` does `labels = [0 if a[1]=='NL' else 1 …]`.
Hard binary; our EMCI/LMCI would be **silently relabelled AD-positive**. The
quietest failure of the five; never copy this. Input hardcoded 181×217×181
(MNI152 1mm). Needs FSL (~10 GB, not pip-installable).

**damianpolak** — split is genuinely patient-level and correct. But two hard
blockers: (a) entry point requires **ADNIMERGE.csv**, which ADNI no longer
ships — the exact reason our step0 exists; (b) `imaging_models/model.py`
imports `pseudo3d_pytorch`, which is neither vendored nor in requirements.
Also `requirements.txt` lists the deprecated `sklearn` shim, which now *raises
on install*. Uses DX (not DX_bl), so EMCI/LMCI collapse to MCI.

**Toqa277** — split is `train_test_split` over plain file indices with no
`stratify=` and no subject parsing at all; structurally cannot be made
subject-level without rewriting the dataset class. But the **backbone is the
best fit**: textbook 3D ResNet-18, `AdaptiveAvgPool3d((1,1,1))` → 512-d vector
→ `Linear(512, num_classes)`. No hardcoded spatial dims in the model, so input
size is free; Grad-CAM target is `layer4`. Labels come from *directory names*,
so 4-class is a trivial change. Preprocessing is ANTsPy-only (pip-installable,
no FSL/FreeSurfer/MATLAB) — by far the most Colab-friendly of the five, though
its notebook has a literal syntax error (`=root_directory = …`) and an
undefined `filename`.

**Recommendation stands:** Toqa277 ResNet-18 for the trunk, NYUMedML's
trunk/head composition idiom for the two heads, Toqa277's ANTsPy chain for
preprocessing.

## 4. IDA PORTAL — WHAT WAS LEARNED

### NIfTI IS available (this was the pivotal discovery)

The Advanced Search "Image Types" checkboxes map to format:

    Type = Original        ->  Format = DCM    (DICOM)
    Type = Pre-processed   ->  Format = NiFTI

Default is Original-only. Searching with the default and downloading would
have silently produced 100% DICOM. **DICOM-only subjects: 0** — every subject
with a baseline structural T1 also has a Pre-processed NIfTI.

### "Weighting = T1" is NOT "a T1 scan"

Of 6,209 T1-flagged baseline hits across 814 subjects, **2,645 were junk**:
localizers (2,267), calibration scans (182), field maps (196). Filtering on
Weighting alone pulls ~40% garbage. Must additionally exclude by Description.

### Baseline visits used

`ADNIGO Screening MRI`, `ADNI2 Screening MRI-New Pt`, `ADNI2 Baseline-New Pt`.
(`ADNI2 Initial Visit-Cont Pt` deliberately excluded — our cohort is ORIGPROT
∈ {ADNIGO, ADNI2}, i.e. new patients.)

### The Subject ID and Image ID fields accept huge pastes

814 comma-separated PTIDs (8,953 chars) and later 811 Image IDs (5,676 chars)
were both accepted with **zero truncation**. Searching by Image ID is the way
to reselect an exact set without clicking 811 checkboxes across 41 pages.

## 5. THE 811-SUBJECT SELECTION (final, agreed, applied)

Rule, implemented in `dataset/mri_raw/select_scans.py`:

1. **Pipeline:** prefer `MT1; GradWarp; N3m`, else `MT1; N3m`.
   Exclude `Spatially Normalized, Masked and N3 corrected T1 image` (already
   skull-stripped + MNI-normalised) and the `HHP`/`HarP` boutique pipelines.
   Reason: mixing preprocessing levels injects a **site-correlated covariate**
   into training, and the normalised variant would collide with running our
   own skull-strip/registration.
2. **Protocol:** prefer non-accelerated (MPRAGE) over accelerated
   (GRAPPA2 / SENSE2 / Accelerated SAG IR-SPGR).
3. **Tie:** scan date closest to `MRI_EXAMDATE`.
4. Determinism guard: lowest Image ID.

Result:

    selected                      :  811  (811 unique PTIDs, 811 unique Image IDs)

### The date_gap red herring — DO NOT "FIX" THIS

`selected_scans.csv` has 8 rows with `date_gap` up to **741 days**. This looks
alarming and is not a defect. Those 8 are exactly the subjects with

Cohort-wide vs clinical baseline: median 15 d, 686/811 within 30 d, max 167 d.

### LONI throughput — measured, not guessed

    3 streams   829 KB/s   (clean, first run)
    10 streams  801 KB/s   + many HTTP 503
    1 stream    340-650 KB/s, and rising overnight

**Concurrency is counterproductive.** LONI returns 503 above ~2 connections
and caps ~0.8 MB/s per account. Control test: with LONI saturated, GitHub
still delivered 6.1 MB/s on the same link, so the cap is account-side, not
bandwidth. Pushing to 10 streams *degraded* throughput to ~145 KB/s for a
while; backing off to 1 stream reversed it. **Use one stream.**

### How to resume

    dataset/mri_raw/_zips/resume.sh            # curl -C -, byte-range resume
    dataset/mri_raw/_zips/resume.sh aria2c     # aria2c -c -x1 -s1 (NOT installed)

Reads `resume_manifest.csv`, skips complete, continues partials from their
exact offsets. Nothing re-downloads.

**URL EXPIRY:** the IDA links expire ~**2026-08-29** (10 days from minting) or
once a download completes server-side. If they 403/404, regenerate via the
collection → ADVANCED DOWNLOAD → "URL List" and replace
`_zips/zip_urls.txt`. Partials stay valid across URL regeneration because
resume is byte-offset based, not URL-bound.

### Manual browser download path (if preferred)

Log in → set study to **ADNI** → Search & Download → Image Collections →
My Collections → `cohort814_baseline_T1_nif` (811) → tick **All** (counter must
read `811 items selected`) → **ADVANCED DOWNLOAD** (not 1-Click, which is one
27 GB zip / "about 1 day") → `Group Files As: 10 Zip Files` → click each link.

Mixing browser-downloaded zips with the existing partials is **safe**:
`unpack_and_verify.py` matches files to subjects by **Image ID**, not by zip
index or filename order.

## 10. STANDING GOTCHAS (session 4 additions)

Everything in context2.txt §9 and context3.txt §9 still applies. New:

- **Use one download stream against LONI.** More is slower and triggers 503s.
- **`Weighting = T1` includes localizers, calibration scans and field maps.**
  Always filter Description as well.
- **Image Type must include "Pre-processed" to get NIfTI.** The default
  "Original" is DICOM-only.
- **`date_gap > 30` in `selected_scans.csv` is expected for 8 subjects** and is
  an artefact of the reference date, not a bad selection. Use
  `gap_to_clinical_baseline`.
- **`pgrep -f` will match the shell running your own command.** Killing
  download processes with `pgrep -f 'pattern'` repeatedly killed the calling
  shell (exit 144). Use the bracket trick — `pgrep -f -- '[-]o cohort814'` —
  or explicit PIDs.
- **Killing `curl` is not enough.** The `bash -c fetch` wrapper shells hold the
  retry loop and will respawn curl after their backoff. Kill supervisors
  top-down: watcher → fetch.sh → xargs → wrapper → curl.
- **IDA collection names are truncated to 25 characters** in the UI.
- **`gh` CLI is not installed**; use `curl` against api.github.com.
- The IDA "Advanced Download" page takes ~60 s to prepare even a small
  collection, and offers a **URL List** link that is far more reliable than
  clicking zip links in the browser.
